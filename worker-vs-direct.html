Worker vs Direct API

Two ways to connect the Feature Intake Pipeline tools to the Anthropic API: what each one does, what it costs, and what you'd need to change to switch.

How each setup works

Direct API (current setup): The tool in the browser calls Anthropic directly, using an API key the visitor pastes into a modal. The key lives in browser memory for that session only. Your Cloudflare Worker is not involved.

Cloudflare Worker: The tool calls your Worker URL instead of Anthropic. The Worker forwards the request to Anthropic using your own API key, which is stored encrypted inside Cloudflare. Visitors enter nothing; the tool just works.

Direct API (current) Cloudflare Worker
Visitor experience Must get their own Anthropic key: 2 min setup, but real friction Just use the tool: no key, no signup
Your cost Zero: visitor's key pays Cents per session, negligible for portfolio traffic
Your API key Not used, not at risk Stored encrypted in Cloudflare, never in browser
Who can use it Anyone willing to get a key Anyone who visits the page
Setup required Already done ~10 minutes of file edits + GitHub push
Cost control Unlimited, not your bill Cloudflare Worker already has origin restriction: only robdull.com can call it

What you'd need to change to use the Worker

Four changes to business-case-index.html and feature-intake-index.html. Nothing changes in Cloudflare: the Worker is already deployed and your API key is already set.

1
Set the Worker URL. Find YOUR_WORKER_URL_HERE (or the current api.anthropic.com fetch URL) and replace with https://tools.rob-dull.workers.dev.
2
Revert the fetch headers. Remove x-api-key and anthropic-dangerous-direct-browser-access from the fetch call. The Worker adds its own key server-side; the browser doesn't send one.
3
Remove the API key modal. Delete the modal HTML, modal CSS, and the showApiKeyModal(), submitApiKey(), and clearApiKey() functions. Remove the key-status pill from the nav.
4
Remove the key check before each run. Delete the if (!getApiKey()) block at the start of the generate() and runStep1() functions.
What the Worker already does for you: it locks incoming requests to robdull.com only, forces the model to claude-sonnet-4-6, caps output at 2000 tokens regardless of what the browser requests, and keeps your API key off the client entirely. None of that requires any changes.

The tradeoff in one sentence each

Direct API costs you nothing but asks visitors to do work before they can try the tool. The key-entry modal signals that this is a serious technical demonstration, but it also means a hiring manager who doesn't have a key will bounce.

Cloudflare Worker costs you cents but removes all friction. Anyone who lands on the page can run the pipeline immediately. For a portfolio tool whose job is to demonstrate capability, that's probably the right call.

Bottom line
The Worker setup is better for a portfolio: zero friction for the people you most want to impress. The direct API setup is better if you want to control who can run the tool or if you want to avoid any API cost entirely. Both are fully functional. Switching from one to the other is a 10-minute file edit.
