The document flow, tool by tool.

What each of the nine tools in the chain actually produces, and where it goes next — every handoff below is a real same-origin localStorage key written by one tool and read by the next, not a conceptual diagram. Four documents carry the most weight for program stakeholders: the BRD, the Roadmap, the Feature list (the extended backlog), and the Jira export. Toggle below to see the evidence and organizational inputs already wired into the chain — support tickets, internal comms, financials, DoR/DoD — alongside it.

01
Persona Generator Discover
A rough user description becomes a detailed enterprise persona — JTBD statement, org context, key interactions, relationship friction.
Produces Persona robdull:personas
Inputs No MCP evidence wired in yet — built from the description you provide.
02
Journey Map Map
Stage-by-stage canvas — actions, goals, touchpoints, emotions, and pain points — seeded from a persona.
Produces Journey / opportunity seeds robdull:journey-seeds · robdull:opportunity-seeds
Inputs Research repo (Dovetail/Notion) Customer support (Zendesk)
03
Initiative Intake Portfolio Tradeoff
Frames one Initiative against competitors, then decomposes it into Business and Architecture Epics with Demand/Feasibility/Viability assumptions and a benefits-realization plan.
Produces Epics (business + architecture) robdull:epics
Inputs Internal comms Financial tracking External comms (NPS, reviews) Analytics Strategic KPIs (recommended)
04
Business Cases Justify
One case per epic — value, cost, strategic alignment, and a rough order-of-magnitude effort estimate that anchors the Epic Prioritizer's job size.
Produces Business Case per epic robdull:business-cases
Inputs Financial tracking External comms
05
Epic Prioritizer Rank
Scores every epic on WSJF and RICE components in one pass. Editable weights recompute the board live — raising risk-reduction can flip an architecture epic to #1 with no re-run.
Produces Epic Ranking + funding line robdull:epic-ranking
Inputs Internal comms (leadership weighting) Customer support (reach/severity)
06
Roadmap & Milestones Schedule
Sequences every prioritized epic — funded first, the rest as capacity frees — into release windows across up to 18 months. Dependencies stay light: named approvals or genuine architecture-epic runway only.
Produces Roadmap robdull:roadmaps
Inputs Delivery systems (sprint velocity) Internal comms (approvals)
07
Business Documents Spec
Standard-template BRD for one funded epic — requirements core (scope, prioritized business requirements, high-level NFRs) plus the executive package (summary, objectives, stakeholders, cost-benefit, sign-off). Refuses epics below the funding line.
Produces BRD robdull:brds
Inputs Internal comms (stakeholders, sign-off) Analytics (what's instrumentable today)
08
Backlog Builder Plan
Turns the BRD into the full delivery-doc suite: MoSCoW'd Features with feature-level NFRs and refined sizing, ordered Stories with BDD acceptance criteria and dependsOn sequencing, a solution outline, security/UAT plan, and dev/user docs. Requirement coverage is computed, not generated.
Produces Feature list (extended backlog) robdull:backlogs (v2)
Inputs Customer support (edge cases → acceptance criteria) DoR / DoD Style guide Current-state architecture
09
Sprint Planner Deliver
MVP scope, a sprint-by-sprint allocation, and a RAID log. Capacity AND dependsOn ordering are both recomputed in code — a story landing no earlier than its dependency raises a visible warning wherever the plan is consumed.
Produces Jira bulk-import CSV Sprint Plan RAID log terminal — exports to Jira, no further handoff

What's real vs. recommended: every chip above except "Strategic KPIs" reflects code that actually runs today — the MCP evidence is fixture-based (PetHealth-flavored, keyless demo data with the same shape a live connector would have) but genuinely wired into each tool's prompts, and every handoff key is a real localStorage write you can inspect in devtools after a run.
